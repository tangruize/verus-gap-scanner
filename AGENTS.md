# Agent instructions

Read `README.md` and `.github/skills/verus-gap/SKILL.md` for setup, scanning and evidence interpretation.

Run `./setup` once, then `./verus-gap /absolute/path/to/project`. Prefer the user's selected scope; the tool handles Cargo setup and bulk probing. An installed wheel provides `verus-gap` and `verus-gap-setup`.

New scans default to level 2: selected-source-only checking that stops when only checking-boundary errors remain. Choose `--scan-level 1` for selected-source-only checking with continued isolation, or `--scan-level 0` for transitive dependency investigation. Cargo dependencies, native controls and repeated confirmation remain intact at every level. Boundary-only stops stay partial and can hide later selected-source gaps; boundaries are not missing library models or successful coverage. Levels are not fixed runtime guarantees. Resume preserves the original level rather than applying the new-scan default, and reuses deliberately finished level-2 boundary frontiers without new probes.

Add `--verbose` for live round progress and confirmed limitation groups; it is display-only and can be changed on resume. Unconfirmed diagnostics and compiler/setup failures are not announced as limitations. Keep the final report and raw evidence.

Use `--jobs N` for a fixed-size process pool; the default is 1 and remains a direct sequential scan. With multiple workers, persistent Python processes take the next file dynamically, avoiding a shared worker GIL. Cache the already parsed/cfg-prepared source models once per pool and load isolated models once per process; never reparse every source for every worker. Workers reuse private writable source copies and render caches, with independent compiler outputs after a single Cargo/setup pass. File state and repeated confirmation are independent; rounds within a file remain sequential. `--verbose` distinguishes cached-model loading, workspace-copy progress, worker PID/readiness, dispatched files and finished files. Choose concurrency for available CPU/memory rather than promising linear speedup. `--jobs` can change on resume; the scan level cannot. The total timeout is shared. Workers publish atomic checkpoints only after completed-round evidence is fully written, including required confirmations; never report unfinished runs or temporary checkpoint files. Only the coordinator writes global reports and the checkpoint index; manual refresh shares the report lock. Ctrl+C waits for active compilers and worker source restoration; worker failures retain a stopped snapshot and exit 2. A forced worker kill cannot run restoration handlers; detect it explicitly and never claim an unrestored copy is restored.

Completed rounds and files refresh reports only when a minute has elapsed and a new confirmed diagnostic/API group exists; repeated locations, boundary/progress-only changes, and file completion do not force another rewrite. Normal exit always refreshes reports, and Ctrl+C saves an interrupted report after restoring sources. Use `./verus-gap report RESULT_DIR` for evidence-only manual refresh, including during a running scan; it does not build, probe, resume, or change the recorded scanner/compiler identity. Preserve `project.json`, `originals/`, and `shards/`, and distinguish unfinished snapshots from finished scans.

Read `report.md`, `report.json`, `review.md`, and `project.json`, including on nonzero exits. Inspect original diagnostics before interpreting a family. Separate reproduced support gaps from setup, instrumentation, local checking boundaries, migration requirements, and compiler failures. Never describe a cleared frontend as a proof or exhaustive inventory.

Do not change input sources, invent contracts, drop Rust derives wholesale, change the target silently, or disable proof lifetime checks. Use `agent-tasks.json` only for a bounded hard blocker, working in a separate copy. Resume preserves evidence and validates identities.
